Μ38 — ΞΕΧΩΡΙΣΤΗ ΕΚΔΟΣΗ ΟΙΚΟΓΕΝΕΙΩΝ / RANK64
05/11/2026

ΠΑΡΑΔΟΣΗ ΚΩΔΙΚΑ ΓΙΑ ΕΛΕΓΧΟ/ΕΚΤΕΛΕΣΗ ΣΤΟΝ SERVER, ΟΧΙ ΑΠΟΤΕΛΕΣΜΑ Μ38.
Η καθιερωμένη καλύτερη έκδοση, το επιτυχημένο Μ37 και προηγούμενα ZIP
έμειναν ανέπαφα. Δεν έγινε καμία απομακρυσμένη σύνδεση/εργασία σε αυτόν
τον κύκλο. Η προεπιλογή είναι τέσσερις διαδοχικές ομάδες, διαθέσιμη και
η επιλογή τριών. Κάθε ομάδα τρέχει παράλληλα σε καθαρή διεργασία.

Η μετάβαση 32->64 bit αφορά ranks, close-map values, scratch και indices.
Οι συντελεστές εξακολουθούν να χρησιμοποιούν 1/2/4/8/16 bytes όπως πριν.
Οι αριθμητικοί πυρήνες δεν ξαναγράφηκαν. Τα caps κάθε μπλοκ ελέγχονται
ακριβώς έως 128 bits πριν από εγγραφές. Το γενικό άνω φράγμα C38² είναι
135-bit και δεν χρησιμοποιείται ως δήθεν 128-bit. Τελικό άθροισμα και
κάλυψη υπολογίζονται με Python integers. Σε μη πιστοποιήσιμο cap υπάρχει
ρητός τερματισμός, χωρίς σιωπηρή υπερχείλιση ή πλασματικό PASS.

Οι υποσύνολοι μεγεθών πρώτου κλάδου χωρίζουν τον αρχικό σταθμισμένο χώρο
ακριβώς. Οι επτά γραμματικές Μ38 των πλάνων 3/4 ομάδων μεταγλωττίστηκαν
πραγματικά στα self-tests και οι καλύψεις αθροίζουν ακριβώς στο C38.
Δεν απαριθμήθηκε πρώτα ο αρχικός Catalan χώρος.

ΕΛΕΓΧΟΙ ΟΡΘΟΤΗΤΑΣ:
- Μ1..Μ12 με 3 και 4 ομάδες και 19.414 ρητά brute-force ζεύγη έως Μ6.
- Boundary ranks έως 6.768.687.869 και τιμές closing map έως 6.541.168.933,
  με tiny cropped arrays και ανεξάρτητη Python-integer αξιολόγηση.
- Αποδοχή μέγιστου 128-bit cap και απόρριψη υπερχείλισης πριν από εγγραφές.
- Ακριβής άμεση ισότητα 610.835.273 συντελεστών, 172.527.156 index values
  και 190.843.586 support values σε 156 στάδια, έως Μ26.
  Οι παλιοί πίνακες κρατήθηκαν σε RAM και συγκρίθηκαν μέσω RAM pipes,
  χωρίς αρχεία πινάκων στον δίσκο.
- Πλήρες Μ28 με την ανέπαφη αναφορά και με 3/4 νέες ομάδες: ίδιο Mn.
- Οκτώ tests σχεδιασμού/πόρων/ακέραιας άθροισης/κλειδώματος.
- Πραγματικός controller Μ6, resume χωρίς επανάληψη και απόρριψη αλλοιωμένου
  αποτελέσματος. Το Μ38 απορρίφθηκε με χαμηλό όριο πριν από arrays.

ΟΛΕΣ ΟΙ ΝΕΕΣ ΑΡΙΘΜΗΤΙΚΕΣ ΔΟΚΙΜΕΣ ΕΓΙΝΑΝ ΤΟΠΙΚΑ ΣΤΑ WINDOWS.
Δεν ισχυριζόμαστε νέα εκτέλεση Linux ή πλήρη αριθμητική Μ38. Το START_M38.sh
εκτελεί πραγματικά τα self-tests στο Linux προτού επιτρέψει την αριθμητική.

ΜΕΤΡΗΣΕΙΣ Μ28 — ΙΔΙΟΣ ΥΠΟΛΟΓΙΣΤΗΣ, 12 ΝΗΜΑΤΑ, 13,73 GiB SOFTWARE CAP,
3 GiB RESERVE, ίδια checked-integer αριθμητική και memory policy full:
backend 32 / 1 ομάδες: υπολογισμοί 6.147 s, controller 9.093 s, RSS 2.157 GiB.
backend 64 / 3 ομάδες: υπολογισμοί 8.195 s, controller 16.453 s, RSS 1.491 GiB.
backend 64 / 4 ομάδες: υπολογισμοί 8.817 s, controller 19.859 s, RSS 1.284 GiB.
Οι controller χρόνοι περιλαμβάνουν imports/καθαρή εκκίνηση και χωριστό
διαγνωστικό Μ12 warm-up σε ΚΑΘΕ worker. Οι χρόνοι υπολογισμών το εξαιρούν.
Η διάσπαση εδώ μειώνει RAM αλλά αυξάνει εργασία/εκκινήσεις. Δεν ισχυριζόμαστε
ταχύτερη νέα έκδοση ή μεταφορά αυτού του ποσοστού στο Μ38.

ΜΝΗΜΗ Μ38:
Πλήρης χωρητικότητα σταθερών scratch/maps: 642422174744 bytes = 598.302 GiB.
Αυτό ΔΕΝ είναι συνολική RSS ή πρόβλεψη κορυφής Μ38. Οι συντελεστές,
stage metadata, υποστηρίξεις και runtime είναι πρόσθετα. Η υποχρεωτική
προεπιλογή 16 GiB reserve και οι φρέσκοι guards διατηρούνται, με πραγματικό
όριο cgroup/διαθέσιμη RAM. Η ονομαστική μνήμη του host δεν υποκαθιστά το όριο.
Αν ομάδα δεν χωρά, σταματά και διατηρούνται οι προηγούμενες ολοκληρωμένες.
Δεν ενεργοποιείται spill ή επανεκτέλεση με δίσκο.

Δεν υπάρχουν matrix files, memmap ή αρχεία συντελεστών στην υλοποίηση.
JSON/logs, caches και εγκατάσταση Python χρησιμοποιούν δίσκο κανονικά και
οι ordinary process I/O counters καταγράφονται χωριστά από matrix I/O.
Δεν έγινε ανεξάρτητη CRT, ούτε προκύπτει από tests τυπική απόδειξη όλου του
λογισμικού ή κλείσιμο παλαιότερης ανοικτής εικασίας καθολικού μεγίστου.
